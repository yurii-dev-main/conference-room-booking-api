# Conference Room Booking API

## Overview
Conference Room Booking API is an asynchronous backend service engineered for conference room reservations, real-time availability discovery, dynamic tariff pricing, and analytical reporting. The platform is implemented using Python 3.12, FastAPI, SQLAlchemy 2.0 (asyncio), PostgreSQL 16, and Alembic migrations.

The service resolves scheduling concurrency, transparent multi-window cost computation, and provides business intelligence metrics regarding facility utilization and revenue generation.

---

## Architecture & Decisions

### Dynamic Tariff Window Pricing Engine
Rental calculations follow an isolated, side-effect-free algorithm (`PricingEngine`). The requested time interval `[start_time, end_time]` is segmented across operating hours (06:00 to 23:00) against predetermined tariff windows with specific multipliers:
- 06:00 - 09:00: 0.90 (10% morning discount)
- 09:00 - 12:00: 1.00 (standard rate)
- 12:00 - 14:00: 1.15 (15% peak surcharge)
- 14:00 - 18:00: 1.00 (standard rate)
- 18:00 - 23:00: 0.80 (20% evening discount)

Sub-hour durations are calculated proportionally based on fractional hours. Fixed supplementary service fees are aggregated additively to the room rental subtotal:
$$\text{Total Price} = \text{Room Rental Cost} + \sum \text{Service Prices}$$

### Concurrency Protection & Race Condition Prevention
To prevent double-booking anomalies during concurrent reservation requests for identical rooms and overlapping timeframes, the service utilizes transactional row-level pessimistic locking (`SELECT ... FOR UPDATE`) on the targeted `Room` entity:
1. A transaction acquires an exclusive row lock on the room record.
2. The system checks for conflicting bookings where `start_time < requested_end AND end_time > requested_start` with confirmed status.
3. If an overlapping booking exists, the transaction fails immediately with HTTP 409 Conflict.
4. If available, the booking is inserted and committed, releasing the lock.

### Historic Price Snapshot Policy
When a booking is confirmed, prices of selected supplementary services are persisted as an immutable snapshot within the booking record. Future price updates or catalog modifications to services do not alter historical booking totals or financial audit logs.

## Getting Started

### Requirements
- Docker (version 20.10 or later)
- Docker Compose (version 2.0 or later)

### Running the Application
1. Clone the repository:
```bash
git clone https://github.com/yurii-dev-main/conference-room-booking-api.git
cd conference-room-booking-api
```

2. Start the service and database:
```bash
docker compose up --build
```
The application will apply Alembic migrations automatically on startup and bind to port 8000.

3. Optional: Seed Initial Data
To populate the database with default rooms (Room A, Room B, Room C) and baseline services (Projector, Wi-Fi, Sound):
```bash
docker compose exec web python -m src.core.seed
```

### Interactive Documentation
- Swagger UI: http://localhost:8000/docs
- ReDoc: http://localhost:8000/redoc
- Health Check: http://localhost:8000/health

## API Reference

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/health` | Service health and liveness check |
| `GET` | `/api/v1/rooms` | List all active conference rooms with attached services |
| `GET` | `/api/v1/rooms/{id}` | Retrieve room details by ID |
| `POST` | `/api/v1/rooms` | Register a new conference room |
| `PATCH` | `/api/v1/rooms/{id}` | Update room properties, rates, or services |
| `DELETE` | `/api/v1/rooms/{id}` | Soft delete room (deactivation; rejected if active future bookings exist) |
| `POST` | `/api/v1/rooms/search` | Search available rooms by time interval and capacity with calculated cost |
| `GET` | `/api/v1/services` | List all available supplementary equipment and services |
| `POST` | `/api/v1/services` | Create new supplementary service in catalog |
| `POST` | `/api/v1/bookings` | Create booking with concurrency lock and price snapshot |
| `GET` | `/api/v1/reports/occupancy` | Calculate room occupancy percentage over operating hours |
| `GET` | `/api/v1/reports/revenue` | Financial revenue report (total, room revenue, services revenue) |
| `GET` | `/api/v1/reports/popular-services` | Services ranked by order count and revenue |

## Business Reports

### Occupancy Report (`/api/v1/reports/occupancy`)
Calculates room utilization percentages relative to operating hours (06:00 to 23:00, 17 hours per calendar day) across a defined date range:
$$\text{Occupancy Rate (\%)} = \frac{\text{Total Booked Hours}}{\text{Operating Hours per Day} \times \text{Days Count}} \times 100$$

### Revenue Report (`/api/v1/reports/revenue`)
Aggregates financial performance across an inclusive date interval, delineating income generated strictly by hourly room rental fees versus revenue generated by supplementary equipment and services.

### Popular Services Report (`/api/v1/reports/popular-services`)
Ranks all registered supplementary services according to client booking frequency and cumulative revenue generated, identifying top-performing offerings.
